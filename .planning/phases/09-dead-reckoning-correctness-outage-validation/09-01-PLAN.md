# 09-01 — Bus-like outage keeps speed and position alive

<objective>
Reproduce the 2026-11-16 bus failure as deterministic tests, then fix the shared Dart DR engine so a constant-speed vehicle does not trip the ZUPT detector when GNSS disappears. Deliver speed continuity, advancing position, growing uncertainty and a valid recovery sequence. Keep this inside the current engine and NavSnapshot contract; native integration and UI work belong to later phases.
</objective>

<context>
Read 09-CONTEXT.md, .planning/ROADMAP.md Phase 9, .planning/REQUIREMENTS.md DR-01/DR-02/DR-03, and mobile/lib/navigation/live_sensor_source.dart. The bus recording showed 50 km/h GNSS-aided driving, then speed collapsing to 1 km/h and a frozen cursor as soon as the 20 s simulated blackout began. Root cause is a ZUPT heuristic that treats near-gravity accelerometer magnitude and low gyro rate as "stopped" — true for steady straight driving. The engine has no clock seam, so tests must first be given one before 20 s of outage and ~14 s of reconvergence can be fast-forwarded. Do not edit roadmap/state, do not touch other phases, and do not replace the engine with the native C ABI.
</context>
