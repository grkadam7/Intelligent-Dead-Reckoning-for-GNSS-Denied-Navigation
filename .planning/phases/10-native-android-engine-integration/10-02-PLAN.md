# 10-02 — Feed the native engine and keep the Dart fallback

<objective>
Route real phone sensors through the packaged C ABI, make the native path satisfy the DR behavior proven in Phase 9, and keep the Dart engine as a safe fallback. This plan ends with the app able to run either engine and with CI proving the native C test.
</objective>

<context>
Read 10-CONTEXT.md, plan 10-01, NENG-02, DR-01..03, native/src/idr_mobile.cpp, mobile/lib/navigation/device_sensor_feed.dart and mobile/lib/map/navigation_screen.dart. The current native engine never resets ENU position from GNSS, only detects blackout on an explicit invalid sample, and grows uncertainty at 0.05 m/s. Without fixing those, switching to it would regress the bus test. This machine cannot load the Android .so; native correctness is verified by a host C test in CI, and engine selection by a Dart fallback test locally.
</context>

  <files>native/src/idr_mobile.cpp, native/CMakeLists.txt, native/tests/test_bus_outage.cpp</files>
  <behavior>On a valid GNSS fix the engine resets ENU position from the fix, sets speed/heading/accuracy and mode GNSS Aided. A blackout is detected when fixes are stale (>1.5 s) or explicitly invalid; at entry the last GNSS speed is carried and never zeroed by steady driving. During the blackout position advances and uncertainty grows monotonically by a speed-scaled rate. Restored fixes produce Recovering then GNSS Aided.</behavior>
  <action>Write the C++ bus-outage test first (RED), using the same shape as mobile/test/fixtures/bus_outage_trace.dart: ~13.9 m/s fixes, near-gravity IMU, 20 s blackout, then restoration. Then modify the C engine and register the test in CMake with BUILD_TESTING. Keep the C ABI and struct layouts unchanged (10-01 contract).</action>
  <verify><automated>CI (ubuntu): cmake -S native -B native/build -DBUILD_TESTING=ON && cmake --build native/build && ctest --test-dir native/build --output-on-failure</automated><manual>None locally (no compiler); CI is authoritative.</manual></verify>
  <done>Native path passes the same observable DR contract as the Dart path.</done>
</task>
